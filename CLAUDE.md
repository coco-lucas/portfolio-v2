# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

This codebase is a **Next.js 16 + React 19 + Tailwind v4 + shadcn/ui boilerplate**, intended to be cloned and adapted for new product apps. Treat the patterns below as the canonical way to do things here — when adding code, match these patterns rather than introducing new ones. The boilerplate ships pre-configured with Portuguese (`pt-BR`) formatters/masks (BRL, CPF/CNPJ); swap them at the locale boundary if a clone targets a different region — don't sprinkle locale-specific code through features.

## Commands

The lockfile is `bun.lock` — use **Bun**.

```bash
bun install
bun dev              # next dev (http://localhost:3000)
bun run build        # next build
bun run start        # next start
bun run lint         # eslint (eslint-config-next core-web-vitals + typescript)
```

No test runner is configured.

## Stack

- **Next.js 16.1.6** App Router, React 19.2, TypeScript strict, Node runtime.
- **Tailwind v4** + **shadcn/ui** (`style: radix-nova`, icons via `hugeicons`). Tailwind tokens live in `app/styles/globals.css` under `@theme inline` — there is no `tailwind.config.*`.
- **next-intl** for i18n; **next-themes** for light/dark.
- **TanStack Query** for server state, **Zustand** (with `persist`) for client state.
- **axios** for HTTP, **sonner** for toasts, **react-hook-form** patterns via shadcn `field`/`input-group` components.

## File & naming conventions

- All source files: **kebab-case** (`use-auth.ts`, `format-cpf-cnpj.ts`, `query-provider.tsx`). Components and pages may be PascalCase *internally* but the file itself is kebab.
- **All types live in `types/`** as `*.d.ts` modules (e.g. `types/auth.d.ts`, `types/user.d.ts`, `types/post.d.ts`). Never co-locate types next to the endpoint, hook, store, or component that uses them — even when only one file imports them today. Augment third-party types here too — see `types/tanstack-table.d.ts` for module augmentation.
- React hooks: prefix with `use-`. Generic UI hooks live in `hooks/`; data-fetching hooks (TanStack Query wrappers around `service/endpoints/*`) live in `hooks/service/`.
- Tests, stories, and other adjuncts (none configured today) co-locate with their subject.

## Folder boundaries — what goes where

| Folder | Purpose | Don't put here |
|---|---|---|
| `app/(public)`, `app/(private)` | Route groups split unauthenticated vs authenticated UI | New top-level route folders unless they need a different auth posture |
| `app/styles/globals.css` | Tailwind v4 `@theme` + CSS variables | Per-component CSS — use Tailwind utilities |
| `components/ui` | shadcn primitives (auto-generated by shadcn CLI) | Hand-rolled components |
| `components/table` | Shared table cells/wrappers built on TanStack Table | Page-specific table code |
| `components/` (top level) | Cross-feature composite components | One-off page sections — keep those next to the page |
| `hooks/` | Generic UI hooks (`use-mask`, `use-pagination`, `use-url-param`, etc.) | Anything that calls the API |
| `hooks/service/` | TanStack Query wrappers around `service/endpoints/*` (one file per domain) | Endpoint definitions, raw axios calls, non-data-fetching hooks |
| `lib/` | Cross-cutting infra: `utils.ts` (cn), `metadata.ts`, `query-client.ts`, `fonts.ts` | Domain logic |
| `service/api.ts` | Single axios instance + interceptors | New axios instances — extend this one |
| `service/endpoints/<domain>.ts` | Two exports: `<domain>Routes` (paths) + `<Domain>Api` (typed request fns) | Hooks, React, toasts — keep this layer pure I/O |
| `store/` | Zustand stores | Server-state caches (use TanStack Query) |
| `i18n/` | next-intl locale resolution and message loading | Per-feature translation files (those go under whatever messages dir the project uses) |
| `types/` | Shared type definitions (`*.d.ts`) and module augmentation | Inline types that only one file uses |
| `utils/` | Pure, framework-agnostic helpers | Anything that imports React, Next, or business state |
| `proxy.ts` (root) | Edge-level rewrites/redirects/headers | Authentication checks (see Proxy section) |

## Path aliases

`@/*` → repo root (`tsconfig.json`). shadcn-specific aliases (`components.json`):
`@/components`, `@/components/ui`, `@/lib`, `@/hooks`, `@/lib/utils`. Always import with `@/` — never use `../../` traversals.

## Architectural patterns

### Auth — axios + zustand + cookie

Three axios interceptors in `service/api.ts` collaborate. Read them as one unit before changing any of them.

1. **Request interceptor** attaches `Authorization: Bearer <accessToken>` from `useAuthStore.getState()`, skipped for paths in `publicRoutes`.
2. **Response interceptor (success + error branch)** opportunistically harvests tokens from `response.data.access`, `response.data.refresh`, or the `x-new-access-token` header and writes them back to the store. It also surfaces user-facing errors via `toastError`.
3. **Refresh interceptor** on 401/403 calls `AuthApi.refresh` exactly once (guarded by `originalRequest._retry`) and replays the original request. Failures *of the refresh call itself* are not retried.

`store/use-auth.ts` is the source of truth, persisted to `localStorage` under `auth-storage`. Critically, it **also mirrors** `{ isAuthenticated, sessionExpiry }` into a non-HttpOnly cookie `auth-session` (`setSessionCookie` / `clearSessionCookie`). The cookie is what the proxy and any server code can read; the access/refresh tokens stay in localStorage. `onRehydrateStorage` checks `sessionExpiry` and force-logs-out on hydration if expired.

**Don't**
```ts
// ❌ New axios instance bypasses interceptors → no auth, no refresh, no error toast
const myApi = axios.create({ baseURL: ... });

// ❌ Mutating auth state without keeping the cookie in sync
useAuthStore.setState({ isAuthenticated: true }); // skips setSessionCookie → proxy can't see it
```

### Data fetching — endpoint → hook → component

Every API call flows through three layers, each with one job. **No layer is allowed to skip its neighbor.**

**1. `service/endpoints/<domain>.ts` — routes + request functions, kept separate.**

The route strings live in their own object so they're enumerable, mockable, and reusable (e.g. by the request interceptor's `publicRoutes` check). The `*Api` object holds *typed* axios calls. This mirrors the shipped `service/endpoints/auth.ts`:

```ts
// service/endpoints/posts.ts
import { api } from "../api";
import type { Post, CreatePostDTO, ListPostsParams } from "@/types/post";

export const postsRoutes = {
  list: "/posts",
  byId: (id: string) => `/posts/${id}`,
  create: "/posts",
} as const;

export const PostsApi = {
  list: (params: ListPostsParams) =>
    api.get<Post[]>(postsRoutes.list, { params }),
  byId: (id: string) =>
    api.get<Post>(postsRoutes.byId(id)),
  create: (data: CreatePostDTO) =>
    api.post<Post>(postsRoutes.create, data),
};
```

Rules for this layer:
- Always export **two** symbols: `<domain>Routes` (paths only) and `<Domain>Api` (functions). Never inline a path inside a function.
- Type both the **request payload** (`CreatePostDTO`) and the **response** (via the `api.get<T>` / `api.post<T>` generic).
- **All types live in `types/<domain>.d.ts`** — never co-locate types next to the endpoint, hook, or component that uses them. DTOs (request shapes) and entities (response shapes) are different types — don't reuse one for the other.
- No React, no hooks, no toasts in this layer. It's pure I/O.

**2. `hooks/service/use-<domain>.ts` — TanStack Query wrapper.**

Components never call `PostsApi.*` directly. Wrap each request in a hook so caching, retries, and invalidation happen consistently. One file per domain, mirroring the endpoint file (`service/endpoints/posts.ts` → `hooks/service/use-posts.ts`):

```ts
// hooks/service/use-posts.ts
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import { PostsApi } from "@/service/endpoints/posts";
import type { CreatePostDTO, ListPostsParams } from "@/types/post";

export const postsKeys = {
  all: ["posts"] as const,
  list: (params: ListPostsParams) => [...postsKeys.all, "list", params] as const,
  byId: (id: string) => [...postsKeys.all, "detail", id] as const,
};

export function usePosts(params: ListPostsParams) {
  return useQuery({
    queryKey: postsKeys.list(params),
    queryFn: () => PostsApi.list(params).then((r) => r.data),
  });
}

export function useCreatePost() {
  const qc = useQueryClient();
  return useMutation({
    mutationFn: (data: CreatePostDTO) => PostsApi.create(data).then((r) => r.data),
    onSuccess: () => qc.invalidateQueries({ queryKey: postsKeys.all }),
  });
}
```

Rules for this layer:
- Export a `<domain>Keys` object so consumers and other hooks share the same cache keys. Hand-rolled key arrays drift.
- Read hooks are `use<Thing>` / `use<Thing>List`; write hooks are `useCreate<Thing>` / `useUpdate<Thing>` / `useDelete<Thing>`.
- Unwrap `.data` here — components should not see axios `Response<T>`.
- All shared types still come from `@/types/<domain>` — don't redeclare hook-specific types inline.

**3. The component — consumes the hook only.**

```tsx
// ✅ Do
const { data: posts, isLoading } = usePosts({ page: 1 });
const { mutate: createPost } = useCreatePost();

// ❌ Don't — bypasses cache, retries, and shared keys
const { data } = useQuery({ queryFn: () => PostsApi.list({ page: 1 }) });

// ❌ Don't — bypasses everything
const { data } = useQuery({ queryFn: () => axios.get("/posts") });

// ❌ Don't — re-creates the imperative call inside the render layer
useEffect(() => { PostsApi.list({ page: 1 }).then(setPosts); }, []);
```

### Server state vs client state

- **Server state** (anything from the API) → TanStack Query. Default `staleTime` is 5 min and `refetchOnWindowFocus` is off (`lib/query-client.ts`); override per-query when needed, don't change the global default casually.
- **Client state** (auth tokens, UI prefs, ephemeral form state) → Zustand or component state.
- **Don't** put server data in Zustand or persist a TanStack cache by hand — they solve different problems.

### Theming / CSS variables

`app/styles/globals.css` follows a deliberate pattern: stable, non-flipping vars are the **source of truth**, and theme-flipping vars are aliases.

```css
:root {
  --foreground-light: oklch(0.145 0 0);
  --foreground-dark:  oklch(0.985 0 0);
  --foreground: var(--foreground-light);   /* alias */
}
.dark {
  --foreground: var(--foreground-dark);    /* re-alias */
}
```

Apply this whenever a UI element has a **fixed-color background** (toast, branded panel, status pill) and needs readable text regardless of the active theme.

**Do** — reference stable handles for fixed surfaces:
```ts
// utils/toast.ts
toast.success(msg, { style: { backgroundColor: "var(--success)", color: "var(--foreground-dark)" } });
```

**Don't** — duplicate raw color values into new vars:
```css
/* ❌ Two sources of truth — drift waiting to happen */
:root { --foreground: oklch(0.145 0 0); --foreground-light: oklch(0.145 0 0); }
```

Semantic colors (`--success`, `--destructive`, `--warning`) are defined per-theme. New status colors should follow the same naming and be defined in both `:root` and `.dark`.

### Metadata

`lib/metadata.ts` exports `defaultMetadata` (mounted in `app/layout.tsx`) and a `createMetadata({ title, description, keywords?, path?, noIndex? })` factory plus an `imageInfo(title?)` helper that returns the OG `images` array.

**Do**
```tsx
// app/(public)/about/page.tsx
import { createMetadata } from "@/lib/metadata";
export const metadata = createMetadata({ title: "About", description: "...", path: "/about" });
```

**Don't** inline OG image objects, hardcode site URLs, or duplicate the title-template logic — extend `websiteConfig` in `lib/metadata.ts` instead.

### Proxy (Next 16, formerly `middleware.ts`)

`proxy.ts` at the repo root currently sets `cache-control: no-store` globally. Next 16's `proxy` is for **redirects, rewrites, and headers** — not the only line of defense for auth. The Next team explicitly recommends re-checking auth/authz inside Server Components, Server Actions, and Route Handlers (the Data Access Layer pattern). Use `proxy` for optimistic UX gating (read `auth-session` cookie → bounce to `/login`) only.

**Don't** import application modules into `proxy.ts` — it can be deployed separately and shared module state is unreliable.

### Internationalization

Locale resolution is in `i18n/locale.ts`; messages are loaded server-side in `app/layout.tsx` via `getLocale()` / `getMessages()` and provided through `<NextIntlClientProvider>`. The boilerplate's `metadata.ts` and shipped formatters default to `pt-BR`/BRL — change `websiteConfig.locale` and the formatter `Intl` locale strings together when forking.

## Utilities catalog

Anything a feature needs that's already built — reach for these before writing new helpers. All are barrel-exported from `utils/index.ts` (or imported directly from `@/lib/...`).

### `cn(...inputs)` — `lib/utils.ts`
`twMerge(clsx(...))`. Use it for **every** conditional className. Never concatenate class strings by hand.

### `utils/toast.ts`
- `toastSuccess(msg)`, `toastError(msg)`, `toastWarning(msg)` — styled wrappers around sonner using `var(--success | --destructive | --warning)` backgrounds and theme-stable foregrounds.
- `toastPromise(promiseOrThunk, { loading, success, error })` — wraps `toast.promise`. Accepts a `Promise<T>` *or* a `() => Promise<T>` thunk. Returns the underlying promise so callers can `await` it.

```ts
// Do
const result = await toastPromise(api.savePost(data), {
  loading: "Saving…", success: "Saved!", error: (e) => `Failed: ${String(e)}`,
});

// Don't — duplicates styling, loses theme-aware behavior
toast.success(msg, { style: { background: "#22c55e" } });
```

### `onError(error)` — `utils/on-error.ts`
Normalizes axios + unknown errors into `{ variant: "destructive", description }`. Use when you need a toast-shaped object for a UI primitive (e.g. shadcn dialogs) rather than just calling `toastError`.

### `capitalize(str)` — `utils/capitalize.ts`
Title-cases each whitespace-separated word. Pure function; safe everywhere.

### `valueOrFallback(value, type?)` and `EMPTY_VALUE` — `utils/value-or-fallback.ts`
Renders `"-"` for null/undefined/empty, otherwise capitalizes and (for `type: "currency" | "percent"`) formats. Use it in table cells and read-only displays so empty states render consistently.

### `utils/formatters/`
- `formatCurrency(n)` / `parseCurrency(s)` — BRL via `Intl.NumberFormat("pt-BR", ...)`.
- `formatDateString(s, dateStyle?, timeStyle?, separator?)` — robust, returns `"-"` for null/invalid input.
- `fmtDate(d: Date)` — `YYYY-MM-DD` for date-input value binding.
- `formatCpfCnpj(value, type?)` — Brazilian doc formatter.

When swapping locales, replace the contents of `utils/formatters/` and `hooks/use-mask.ts` together — the masks and formatters are paired.

### Hooks — `hooks/`
- **`useMask()`** → `{ applyMask, removeMask, getMaxLength, validateMask, maskPatterns }` for CPF/CNPJ/phone/cep/date/currency. Includes real CPF/CNPJ checksum validation. Wire `applyMask` to `onChange`, `removeMask` before submitting, `validateMask` for client-side validation.
- **`useUrlParam(key, defaultValue?)`** → `[value, setValue]`. Drives state from URL search params via `router.replace` (no scroll). Use it for any state that should survive refresh / be shareable.
- **`usePagination({ defaultPageSize? })`** → `{ currentPage, pageSize, setCurrentPage, setPageSize }`. Built on `useUrlParam`; updates `?page` and `?page_size` in a single `router.replace` to avoid double-navigation.

**Do** drive table pagination from `usePagination` so URLs are shareable.
**Don't** call `useUrlParam` for `page`/`page_size` directly — `usePagination` already coordinates the two.

### `queryClient` — `lib/query-client.ts`
Single shared client. Don't construct another. Mounted via `app/query-provider.tsx` inside `app/layout.tsx`.

### `Toaster` — `components/ui/sonner.tsx`
Mounted once in `app/layout.tsx`. Already wired with hugeicons and the `--popover` / `--popover-foreground` tokens. Don't mount a second `<Toaster />`.

### `fontsVariables` — `lib/fonts.ts`
Spread onto `<html className=...>`. Adding a font means adding it here, not in component code.

## How to add things

- **A new page** → place under `app/(public)/<route>/page.tsx` or `app/(private)/<route>/page.tsx`. Export `metadata` via `createMetadata`. Use Server Components by default; only mark `"use client"` when you need state, effects, or browser APIs.
- **A new API endpoint group** → three coordinated files:
  1. `types/<domain>.d.ts` — entities + DTOs.
  2. `service/endpoints/<domain>.ts` — `<domain>Routes` (paths) and `<Domain>Api` (typed functions calling `api.*`).
  3. `hooks/service/use-<domain>.ts` — `<domain>Keys` cache keys + `use<Thing>` / `useCreate<Thing>` / `useUpdate<Thing>` / `useDelete<Thing>` wrappers. Components import from here only.
- **A new shadcn primitive** → `bunx --bun shadcn@latest add <name>` (it knows the aliases from `components.json`). The `style: radix-nova` and hugeicons preferences flow through automatically.
- **A new utility** → if pure & framework-agnostic, `utils/<kebab-name>.ts` (and re-export from `utils/index.ts` if generally useful). If it touches React/Next, it's not a util — it's a hook or a component.
- **A new Zustand store** → `store/use-<thing>.ts` following `use-auth.ts` (same `persist` + `partialize` + optional `onRehydrateStorage` shape).
- **A new locale-sensitive formatter or mask** → add to `utils/formatters/` or extend `hooks/use-mask.ts`. Keep the `Intl` locale string consistent across the pair.

## Anti-patterns to reject on sight

- New axios instances or raw `fetch` for app API calls — use `api` from `service/api.ts`.
- `localStorage`/cookie reads scattered through components — auth state goes through `useAuthStore`; URL-driven state goes through `useUrlParam`.
- Hand-built `className` concatenation — use `cn()`.
- Tailwind classes mixed with raw `style={{ color: "#xxx" }}` — define a CSS var if needed.
- Duplicating `oklch(...)` values into a new var (see Theming).
- Auth checks only in `proxy.ts` — also re-verify in Server Components / Route Handlers.
- Putting server data into Zustand "to cache it" — that's TanStack Query's job.
- Data-fetching hooks living flat in `hooks/` — they belong in `hooks/service/<domain>`.
- Components calling `*Api.*` (or `axios.*`, or `fetch`) directly — go through a `hooks/service/` hook.
- Types declared inline in an endpoint, hook, store, or component — move them to `types/<domain>.d.ts`.
- Endpoint files that mix the route string into the request function — keep `<domain>Routes` and `<Domain>Api` separate (see `service/endpoints/auth.ts`).
- Translating user-facing strings inline — go through next-intl messages.
- Editing `app/styles/globals.css` to add page-specific styles — extend the design tokens or use Tailwind utilities instead.
